# Анализ аналогов и продуктовые решения Foody

Цель анализа — понять, что в популярных трекерах КБЖУ работает хорошо, что раздражает, и какие решения
взять в личное приложение для одного пользователя с локальным хранением данных.

## Что смотрели

| Приложение | Модель | Сильные стороны | Слабые стороны для нашей задачи |
|---|---|---|---|
| **MyFitnessPal** | freemium, премиум ~$80/год | Самая большая база продуктов (20+ млн), сканер штрихкодов, сохранённые приёмы пищи и рецепты, привычный дневник по приёмам | База краудсорсинговая — ошибки в 12–25 % записей; сканер штрихкодов ушёл в платную подписку; аккаунт и облако обязательны; много рекламы и лишних экранов |
| **FatSecret** | бесплатно | Полностью бесплатен, есть Б/Ж/У, сахара, клетчатка; понятный дневник | Данные тоже краудсорсинг, интерфейс перегружен, без офлайн-приватности |
| **YAZIO** | freemium | Приятный дизайн, рецепты, кольца прогресса, недельная статистика | Ключевые отчёты и часть нутриентов — за подпиской; европейская база, но качество записей плавает |
| **Lifesum** | freemium | Красивый онбординг и планы питания, оценка «качества» приёма пищи | Ориентация на диеты/планы, а не на точный учёт; подписка |
| **Cronometer** | freemium | Точная база (USDA/NCCDB), 84 микронутриента, отчёты по всем нутриентам | Тяжёлый интерфейс, продуктов из европейских магазинов часто нет — вводить вручную |
| **MacroFactor** | только подписка (~$72/год) | Адаптивный алгоритм целей по динамике веса, быстрый ввод, отличная «недельная сводка» | Нет бесплатного уровня; целей «вручную» мало кто использует, но нужен вес каждый день |
| **FoodNoms** (iOS) | freemium | Локальные данные + iCloud, приватность, сканер этикеток (OCR таблицы), красивый нативный SwiftUI | Только английские/US-этикетки в сканере; часть функций платная |
| Российские (Дневник питания, Мой здоровый рацион, Калорийка и др.) | бесплатно/реклама | Русские названия продуктов, простые дневники | Реклама, устаревший интерфейс, база плохо покрывает европейские магазины |

## Общие наблюдения

1. **Главная боль — качество данных о продукте.** Краудсорсинговые базы содержат ошибки, а европейские
   продукты часто отсутствуют. Все «большие» приложения решают это сканером штрихкодов, но он ведёт в ту же
   базу. Прямое считывание **таблицы пищевой ценности с упаковки** даёт данные производителя.
2. **Быстрый ввод повторяющейся еды важнее всего.** Сохранённые приёмы пищи («мой обычный завтрак»),
   недавние/частые продукты, копирование — то, чем пользуются каждый день.
3. **Рецепты считают по сумме ингредиентов**, а пересчёт на вес готового блюда и порцию есть не везде
   (MFP, Cronometer умеют, YAZIO частично). Без этого каши и супы считаются неверно.
4. **Статистика.** Кольцо калорий + три полоски макросов на экране дня стали стандартом. Недельная сводка
   с «перебором/недобором» относительно цели есть у MacroFactor и Cronometer; у остальных — только графики.
5. **Разбивка по приёмам пищи** есть в MFP (в отчёте), у остальных слабо.
6. **Приватность.** Почти все требуют аккаунт и хранят данные в облаке. FoodNoms показал, что локальные
   данные и нативный интерфейс — самостоятельная ценность.

## Что взяли в Foody

- **Дневник по приёмам пищи** (завтрак / обед / ужин / перекусы), кольцо калорий и полоски Б/Ж/У с целями
  на экране дня, остаток калорий и бейдж перебора — как у лучших аналогов, но без лишнего.
- **Продукты по этикетке.** Полный набор полей декларации ЕС (Регламент 1169/2011): энергия в кДж и ккал, жиры,
  насыщенные, моно-/полиненасыщенные, транс, углеводы, сахара, полиолы, крахмал, клетчатка, белки, соль (и натрий),
  холестерин, алкоголь, витамины и минералы с % NRV. Ввод вручную или **фото → LLM → заполненная карточка**,
  которую остаётся проверить.
- **Сохранённые приёмы пищи** — набор продуктов с количествами, добавляется одним касанием, разворачивается в
  отдельные правимые записи.
- **Рецепты** с расчётом на 100 г готового блюда по **взвешенному весу после приготовления** и на стандартную порцию.
- **Статистика день / неделя / месяц**: калории по дням с линией цели и раскраской «в норме / перебор / недобор»,
  средние Б/Ж/У с бейджами перебора/недобора, разбивка по приёмам пищи (доля и КБЖУ), клетчатка/сахара/соль против лимитов.
- **Цели** с историей (статистика прошлых недель считается по тогдашним целям) и калькулятором Миффлина — Сан Жеора.
- **Только локальные данные** (SwiftData на устройстве), резервная копия одним JSON-файлом, ключи API — в Keychain.
- **Минималистичный интерфейс**: системные шрифты, спокойная палитра, карточки, тёмная тема, оптимизация под ширину iPhone 11.

## Что сознательно не делали (пока)

- Штрихкоды и внешние базы (Open Food Facts) — можно добавить позже как второй источник; требует сети и
  доверия к краудсорсингу.
- Учёт воды, веса тела, шагов, интеграцию с Apple Health — вне задачи.
- Облачную синхронизацию — противоречит требованию «все данные на телефоне».
