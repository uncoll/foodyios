# Выбор модели для распознавания этикеток

## Задача

По фото таблицы пищевой ценности (любой язык ЕС, иногда США) получить JSON со значениями **на 100 г / 100 мл**:
энергия (ккал, кДж), жиры, насыщенные, углеводы, сахара, клетчатка, белки, соль + необязательные поля
(моно-/полиненасыщенные, полиолы, крахмал, натрий, витамины…). Модель должна:

- брать колонку «на 100 г», а не «на порцию» и не «% RI»;
- копировать числа как напечатано (запятая = точка), не досчитывать то, чего нет;
- пересчитывать из порции только если размер порции указан в г/мл, иначе честно возвращать `null`;
- отвечать строго по JSON-схеме (structured outputs), чтобы приложение не парсило свободный текст.

Инструкция и схема одинаковы для всех моделей и для приложения: `tools/label-bench/prompt.txt`,
`tools/label-bench/schema.json` (в Swift — `FoodyCore/Sources/FoodyCore/LabelParsing/LabelParseSpec.swift`).

## Тестовый набор (18 фото)

Сетевые ограничения облачного контейнера (доступ только к GitHub) не позволили скачать фото с Open Food Facts или
Wikimedia напрямую, поэтому набор собран так:

| Группа | Кол-во | Описание |
|---|---|---|
| Реальные фото из GitHub | 4 | UK-этикетка печенья на красной фольге с бликами (Open Food Facts, `openfoodfacts-dart`); 3 американских «Nutrition Facts» (сок 240 мл — пересчёт из порции; сок «1 bottle» без размера — правильный ответ `null`; хлеб 28 г — размытое фото) |
| Синтетические этикетки | 14 | HTML-таблицы, отрисованные Chromium и «испорченные» как фото: перспектива, поворот до 4°, цилиндр банки/бутылки, блики, тени, шум, размытие, JPEG 45–90, уменьшение до 0,55×. Языки: de ×2, fr ×2, it ×2, es ×2, pl, nl, cs, ru ×2, en. Раскладки: одна колонка; «на 100 г + порция»; «+ % RI»; тёмный фон; строчный русский текст «белки – 7,5 г…»; таблица с витаминами; `<0,01 g`; только натрий и т. п. |

Эталон для синтетики точный (значения известны), для реальных фото расшифрован вручную. Скрипты и данные:
`tools/label-bench/` (см. `data/ATTRIBUTION.md`). Workflow `label-bench.yml` умеет **дополнить набор реальными фото
с Open Food Facts** (8 стран) — он запускается на GitHub Actions, где сеть не ограничена.

## Метрика

9 полей на фото: ккал, кДж, жиры, насыщенные, углеводы, сахара, клетчатка, белки, соль. Поле засчитывается, если
значение совпало с эталоном (допуск ±1 ккал / ±2 кДж / ±0,05 г + 0,5 %; для пересчёта из порции допуск шире).
Отдельно считаются **пропуски** (на этикетке есть, модель вернула `null`) и **выдуманное** (на этикетке нет —
например, кДж на американских этикетках — а модель посчитала сама).

## Результаты: модели Claude

Прогон выполнен через субагентов Claude Code (по одному агенту на модель, каждый видел все 18 фото по той же
инструкции; ответы сохранены в `tools/label-bench/results/anthropic-agent/`). Стоимость посчитана по формуле
токенов Anthropic для изображения (w × h / 750) + инструкция ≈ 700 токенов + ответ ≈ 350 токенов и ценам
сентября 2026 (Haiku 4.5 $1/$5, Sonnet 5 $2/$10, Opus 5 $5/$25, Fable 5.1 $10/$50 за 1 млн токенов вход/выход).

| Модель | Точность полей | Фото без единой ошибки | Ошибки / пропуски / выдумано | $/фото (оценка) | $/1000 фото |
|---|---|---|---|---|---|
| Claude Opus 5 | **100 %** | 18/18 | 0 / 0 / 0 | 0,019 | 18,6 |
| Claude Sonnet 5 | 99,3 % | 17/18 | 1 / 0 / 0 | **0,007** | 7,4 |
| Claude Fable 5.1 | 99,3 % | 17/18 | 1 / 0 / 0 | 0,037 | 37,2 |
| Claude Haiku 4.5 | 92,1 % | 14/18 | 9 / 0 / 2 | 0,004 | 3,7 |

Разбор ошибок:

- **Sonnet 5 и Fable 5.1** ошиблись только в одном поле самого тяжёлого кадра (`s12_fr_soup_hard`: сильное размытие,
  JPEG 45, уменьшение 0,6×): соль 0,8 вместо 0,6 г. Обе модели сами поставили `confidence: low` — приложение
  показывает это предупреждение в форме проверки.
- **Haiku 4.5**: на том же размытом кадре ошиблась в 8 полях из 9; на польском хлебе неверно прочитала клетчатку
  (4,1 вместо 6,1); на двух американских этикетках **досчитала кДж**, хотя их нет на этикетке (нарушение правила
  «не вычислять»). При этом все хорошо читаемые этикетки (14 из 18) распознаны без ошибок.
- **Opus 5** не ошиблась ни разу, включая размытый кадр и «ловушку» с бутылкой без размера порции.
- Все четыре модели правильно обработали «`<0,01 g`», строчный русский формат, колонки «на порцию» и «% RI»,
  тёмный фон, цилиндрическое искажение и правильно вернули `null` для этикетки без размера порции (кроме
  обсуждённых ошибок Haiku).

### Оговорки

- Прогон шёл не через API, а через агентов Claude Code: у моделей было включено размышление и картинка передавалась
  средствами инструмента Read (≤ 2000 px). Точность через API с той же инструкцией ожидается близкой, но
  стоит проверить на своём ключе — workflow `label-bench.yml` (поле `anthropic_api_key`) делает это автоматически
  и пересчитывает таблицу по реальным токенам из `usage`.
- 18 фото — небольшой набор; разница 99,3 % против 100 % — одна ошибка на одном намеренно испорченном кадре.

## Модели OpenAI

Из облачного контейнера доступ к `api.openai.com` закрыт сетевой политикой, поэтому прогон OpenAI подготовлен,
но **ещё не выполнен**. Как запустить (займёт ~10 минут, стоимость < $2):

1. В репозитории должен быть установлен GitHub App «Claude» или просто откройте GitHub → Actions →
   **Label parsing benchmark** → Run workflow.
2. `stage = all` (или `openai`), в поле `openai_api_key` вставьте ключ (он передаётся во вложенный workflow как
   секрет и маскируется в логах), `openai_models` можно оставить пустым — скрипт сам возьмёт актуальные модели
   (`gpt-5.6-luna/terra/sol`, `gpt-5*-mini/nano`, `gpt-4.1*`, `gpt-4o*`) из `/v1/models`.
3. Workflow скачает ещё ~15 реальных фото с Open Food Facts, прогонит модели, пересчитает `results/summary.md`
   и закоммитит всё в ветку. Итоговая таблица появится в `tools/label-bench/results/summary.md`.

Ориентир по ценам OpenAI (сентябрь 2026, открытые источники; уточните на platform.openai.com): GPT-5.6 Luna
$1/$6, Terra $2,5/$15, Sol $5/$30, gpt-5-mini $0,25/$2, gpt-4.1-mini $0,4/$1,6 за 1 млн токенов. По цене
Luna сопоставима с Haiku/Sonnet, Sol — с Opus. Приложение поддерживает оба провайдера (Responses API со
structured outputs), так что после прогона достаточно переключить модель в Настройках.

## Рекомендация

**По умолчанию — Claude Sonnet 5** (`claude-sonnet-5`): практически безошибочна (99,3 %), ~0,7 ¢ за фото,
т. е. около $2 в месяц при 10 сканированиях в день. Если фото сложное (блики, размытие) и модель пометила ответ
`low`, стоит переснять или переключиться на **Claude Opus 5** (100 %, ~1,9 ¢ за фото). **Haiku 4.5** в 2 раза
дешевле Sonnet, но делает реальные ошибки и досчитывает значения — для дневника, где важна точность, экономия
в $1 в месяц того не стоит. Fable 5.1 не даёт прироста точности при 5-кратной цене.

Практические выводы, зашитые в приложение:

- фото уменьшается до 1600 px по длинной стороне и кодируется в JPEG 0,88 — так же, как в бенчмарке
  (меньше токенов, точность не страдает);
- используется structured output по строгой схеме, поэтому ответ всегда парсится;
- предупреждение `confidence`/`notes` модели показывается над формой — пользователь проверяет цифры перед сохранением;
- усилие рассуждения по умолчанию `low` (быстро и дёшево), в Настройках можно поднять.
